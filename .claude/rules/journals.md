# Документы и журналы: что куда писать

Знание и дела живут в файлах, а не в чате: следующая сессия видит только файлы.

| Что | Где | Язык | Когда |
|---|---|---|---|
| Суть мода, как устроен и почему так | `mods/<id>/CLAUDE.md` | рус | вместе с кодом |
| Возможности, версии, сборка — для людей | `mods/<id>/README.md` | рус | поменялось поведение для игрока; таблицу целей пишет `npm run sync` |
| Изменения для игроков | `mods/<id>/docs/CHANGELOG.md`, раздел `[Unreleased]` | англ | в том же коммите, что и изменение, заметное игроку |
| Страница проекта на Modrinth | `mods/<id>/docs/MODRINTH.md` | англ | новая возможность |
| Галерея Modrinth | `mods/<id>/docs/gallery.json` + `docs/screenshots/` | англ | после `updateScreenshots` |
| Различия API между версиями Minecraft | `porting.md` скилла `fabric` | рус | наткнулся при переходе на новую цель |
| Наши дела | `docs/TODO.md` (общие) и `mods/<id>/docs/TODO.md` | рус | предложил и не делаю сейчас, отложили, ждёт проверки или ответа |

- **CHANGELOG** — Keep a Changelog: подразделы `### Added / Changed / Fixed / Removed…`, одна строка на пункт — что изменилось для игрока, а не как сделано. Поддержка новой версии Minecraft без изменений мода — не пункт: это сборка той же версии под новую игру (порт, скилл `release`). Формат и связь с `mod_version` сверяет `check-changelog`.
- **TODO — итог, а не ход обсуждения.** Разделы — статусы: «Предложено», «Согласовано», «Проверить вживую», «Ждёт». Пункт — `- [ ] YYYY-MM-DD · что и зачем`; сделанный удаляется в том же коммите — история в git. Пока пользователь выбирает в разговоре — в журнал не пишем; отложил («потом») — пишем; всплыло дело, которое сейчас не делаем, — «Предложено» с датой, и в ответе говорю, куда записал. Хук завершения хода ищет предложения без записи в TODO, формат сверяет `check-journals`.
